# Day 32 — Research Workflow & Task Decomposition

**Objective:** Teach the agent to break a complex research question into smaller, manageable tasks before trying to answer it.

---

## 📖 Theory

### Task decomposition

Task decomposition means splitting one large, complex goal into several smaller, more specific subtasks that are each easier to research individually. A single vague question is hard to search for effectively; a set of specific subtasks is much easier to act on one at a time.

**Example:**

```
User:
Should a startup use AI agents for customer support?

        ↓

Agent breaks it into:

1. What are AI agents?
2. Current customer-support applications
3. Benefits
4. Limitations
5. Costs
6. Risks
7. Recommendations
```

### Planning

Planning is the step where the agent decides *what* subtasks are needed and in *what order*, before actually executing any of them. This happens before any tool is called — it's a reasoning step, not an action step.

### Subtasks

A subtask is one specific, narrower piece of the overall research question — small enough to search for directly and get a useful, focused result.

### Sequential execution

Once a plan exists, subtasks are typically executed one at a time (sequentially), with each result potentially informing later steps. This is simpler and more predictable than trying to research everything simultaneously.

### The research workflow

```
Plan → Execute → Synthesize
```

- **Plan** — break the question into subtasks
- **Execute** — search/gather information for each subtask
- **Synthesize** — combine everything into one coherent final answer

## 🐞 Common Errors

| Error | Likely Cause | Fix |
|---|---|---|
| Too many subtasks | No limit given to the planning prompt, so the model generates an excessive list | Explicitly instruct the model to generate a bounded range (e.g., 5-7 subtasks) |
| Duplicate subtasks | Planning prompt doesn't guide the model toward distinct angles | Ask explicitly for non-overlapping subtasks covering different aspects |
| Unrelated searches | A subtask drifts from the original research question | Include the original question as context when generating subtasks, not just a generic planning prompt |
| No final synthesis | Subtask results are collected but never combined into one coherent answer | Add an explicit synthesis step after all subtasks are executed, not just a results dump |
